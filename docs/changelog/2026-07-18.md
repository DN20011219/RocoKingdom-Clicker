# 更新日志 — 2026-07-18

记录 2026-07-18 ~ 2026-07-20 的变更，主要内容：鼠标锚点路径扰动系统、PathPlanner 双策略引擎、驱动硬件时间戳修复、锚点热键可配置化。

## 主要变更

### 1. 鼠标锚点路径扰动系统

- **录制时标记锚点**：录制过程中按锚点热键（默认 F12）标记锚点位置。`InputRecorder` 拦截锚点键的 down/up 双向事件，避免泄漏到录制数据中。锚点事件仅记录时间戳，不记录绝对坐标。
- **起始锚点自动注入**：录制开始时自动在事件列表开头插入一个 `AnchorEvent(t=0)`，确保第一段移动（录制开始 → 首个手动锚点）也能参与路径扰动。
- **纯相对位移向量**：回放时按锚点分段，累加段内所有相对移动量得到位移向量 `(total_dx, total_dy)`，全程不使用绝对坐标，避免坐标漂移。
- **回放精确保证**：`PathPlanner._to_moves()` 最后一步校正所有舍入误差，确保每段总位移与原始录制完全一致。无论使用何种策略、何种随机种子，每个锚点处的累积位移零偏差。
- **no-op 占位保持时序**：锚点事件被过滤后插入 `move(x=0, y=0)` 保持时间戳连续，避免锚点边界出现时间空隙。
- **锚点 Toast 通知**：录制时按下锚点键立即弹出 toast 提示「📌 锚点 #N 已标记」，不受 0.5s 节流限制。

### 2. PathPlanner 双策略引擎

新增 `PathPlanner.py` 路径扰动引擎，支持两种可切换策略：

- **sine 策略（正弦垂直扰动）**：
  - 在累积路径的垂直方向叠加正弦波偏移：`amplitude * sin(freq * 2πu + phase) * sin(πu)`
  - `sin(πu)` 包络保证首尾扰动 = 0，终点精确不变
  - 步长几乎不膨胀（原始 22px → 扰动后仍约 22px）
  - 每轮回放路径不同但终点一致

- **fitts 策略（拟人化路径）**：
  - 平滑低频噪声：叠加 2~4 个随机频率正弦波（0.5~3.0Hz），步间自然相关，模拟手臂惯性运动
  - 垂直弧线偏移：`arc_amp * sin(arc_freq * πu + arc_phase) * sin(πu)` 包络
  - 过冲修正：30% 概率在 70%~85% 进度处沿运动方向冲过头，smoothstep 平滑过渡后修正
  - 自适应缩放：距离越远扰动越大（上限 1.5 倍）
  - 平滑度提升 2.3 倍，接近原始路径质量

- **策略切换**：`PlaybackEngine.path_strategy` 属性控制，默认 `"fitts"`。`PathPlanner(strategy="sine"|"fitts")` 初始化时选择。

### 3. 驱动硬件时间戳修复

- **问题**：`interception_wait` 阻塞 → `interception_receive` 批量取事件 → Python 循环用 `time.perf_counter()` 打时间戳。batch 内事件在微秒内处理完，时间戳几乎相同，丢失了真实间隔，导致回放时动作加速。
- **修复**：使用 `InterceptionMouseStroke.information` / `InterceptionKeyStroke.information` 字段（Windows 硬件级时间戳，毫秒，等同 `GetTickCount()`）作为事件时间源。
- **键盘偏移修正**：`MouseStroke.information` 在 offset 16，`KeyStroke.information` 在 offset 4。键盘事件必须用 `ctypes.memmove` 从正确偏移读取，否则会读到错误数据。
- **Fallback 机制**：`information == 0` 时（虚拟化环境等罕见情况）回退到 `perf_counter()`。

### 4. 锚点热键可配置化

- **从硬编码改为可配置**：锚点热键从固定 `0x58`（F12）改为通过 `hotkeys.json` 配置，用户可改为其他 F1-F12 键。
- **配置持久化**：`hotkeys.json` 新增 `"mark_anchor": "F12"` 字段。
- **UI 常驻提示**：快捷键面板新增「标记锚点（录制中）」配置行和彩色按键徽章，与其他 4 个热键统一显示。
- **互斥检测**：`InputRecorder.set_hotkeys()` 新增 `anchor` 参数，4 键（start/stop/cancel/anchor）互斥检查。

### 5. 旧录制文件兼容

- **F12 泄漏事件过滤**：`PlaybackEngine._is_leaked_f12()` 检测并过滤旧版录制中泄漏的 F12 key up 事件（旧版未吞掉 F12 up，导致回放时多发 F12 键击）。

## 变更影响的文件

- **`PathPlanner.py`**（新增）
  - 路径扰动引擎，`generate_path(total_dx, total_dy, original_moves, seed)` 主入口
  - `_sine_strategy()`：正弦垂直扰动
  - `_fitts_strategy()`：平滑低频正弦波 + 弧线 + 过冲
  - `_to_moves()`：累积浮点路径 → 整数移动量 + 最后步校正
  - `_cumulative()` / `_norm_times()`：工具方法

- **`InputRecorder.py`**
  - 新增 `AnchorEvent` 数据类（仅含时间戳）
  - `start()` 自动注入起始锚点
  - `_capture_loop()` 改用 `stroke.information` 硬件时间戳，键盘用 `memmove` 从正确偏移读取
  - `_handle_keyboard_event()` 锚点检测改为 `self.HOTKEY_ANCHOR`（可配置）
  - `set_hotkeys()` 新增 `anchor` 参数，4 键互斥检查
  - 新增 `HOTKEY_ANCHOR` 实例属性
  - F12 down/up 双向拦截，不泄漏到录制数据

- **`PlaybackEngine.py`**
  - 新增 `_anchors` 属性、`path_strategy` 属性
  - `_preprocess_events()` 按锚点分段调用 `PathPlanner.generate_path()`
  - `_parse_anchors()` 解析锚点索引和时间
  - 新增 `_is_leaked_f12()` 旧文件兼容过滤
  - 回放循环移除 `cursor_jump` 处理（纯相对模式）

- **`ConfigManager.py`**
  - `DEFAULT_HOTKEYS` 新增 `"mark_anchor": "F12"`
  - `HOTKEY_LABELS` 新增 `"mark_anchor": "标记锚点（录制中）"`

- **`Clicker.py`**
  - `_init_recorder()` 注册 `on_anchor` 回调
  - `_apply_hotkeys_to_recorder()` 传递 `anchor` 热键
  - 新增 `_on_anchor_marked(n)` toast 回调

- **`webview.py`**
  - `_hotkey_labels` 新增 `"mark_anchor"` 配置项

- **`hotkeys.json`**
  - 新增 `"mark_anchor": "F12"`

## 快速验证步骤

1. 录制一段包含鼠标移动的脚本，录制中按 F12 标记几个锚点，确认：
   - 屏幕弹出 toast「📌 锚点 #N 已标记」
   - 保存后 JSON 中包含 `"type": "anchor"` 事件
2. 回放该脚本多次，确认：
   - 每次回放路径略有不同（鼠标轨迹弧线/抖动不同）
   - 每个锚点处鼠标最终到达的位置完全一致
   - 回放速度与录制时一致（不会加速）
3. 在快捷键面板修改锚点热键（如改为 F11），保存后重新录制，确认新热键生效
4. 快速移动鼠标录制，检查 JSON 中相邻 move 事件的 `t` 差值有合理的毫秒级间隔

## 调试与注意事项

- PathPlanner 默认使用 `fitts` 策略，切换策略需在代码中设置 `PlaybackEngine.path_strategy = "sine"`
- 锚点系统采用纯相对位移模式，不依赖绝对坐标，因此不受录制起始位置影响
- 硬件时间戳 `information` 字段为 32 位无符号整数，约 49.7 天回绕一次，正常录制不会触发
- 旧录制文件（无锚点数据）回放时行为不变，`_is_leaked_f12()` 自动过滤泄漏事件
