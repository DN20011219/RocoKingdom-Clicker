# 更新日志 — 2026-10-01

两处清理：删掉第四栏与 `F6` 完全等价的重复按钮；把 `data/clicker.log` 移出版本控制。

## 1. 删除重复的「🎙 录制区域」按钮

昨天（[2026-09-30](2026-09-30.md)）把三个区域捕获入口统一到 `ClickerManager.request_region_capture()` 之后，「🎙 录制区域」和「📐 拖拽圈选」变成了**完全等价**的两个按钮：都投递 `mode="drag"`，都调用 `RegionSelector.select_by_drag()`，区别只剩前者多绕一跳请求队列（约 0.5 秒延迟）。

保留它唯一的价值是在面板上给 `F6` 一个可见对应物——但这个价值现在由拖拽圈选按钮自己承担了：

- **`webview.py`**：删除第三个按钮；`_rc_record_btn` 改指向拖拽圈选按钮，热键刷新逻辑于是把标签写成 `📐 拖拽圈选 (F6)`。两个按钮的右侧留白改为只有前者有（`padx=(0, 4) if mode == "drag" else 0`），否则末位按钮会多出一条空隙。
- 顺带消除了一个命名误解：「录制区域」很容易被读成"录制区域内的操作"，而真正的录制是 `F7` 那套。

**没有改的**：`HOTKEY_LABELS` 里的 `record_region → "录制区域（圈选）"`、README 热键表、以及 toast 文案 `✓ 已录制区域 X,Y,W,H`。前两者是**热键**的显示名（改它会影响热键配置面板和已存的 `hotkeys.json` 语义），第三者是个动宾短语而非按钮名，都跟这次删按钮无关。

- **`Clicker.py`**：`request_region_capture()` 的 docstring 里"三个按钮"改为"捕获按钮（拖拽圈选 / 拾取窗口）"。
- **`README.md`**：界面说明改为两个按钮；「三个入口，一套互斥规则」改为「两个入口」。

## 2. `data/clicker.log` 移出版本控制

`.gitignore` 第 11 行一直有 `data/clicker.log`，但这个文件在规则写下之前就已经被跟踪了——**`.gitignore` 对已跟踪文件无效**，所以每次跑程序都会产生一条 `M data/clicker.log`，日志内容（含本地路径、演奏记录）也会进公开历史。

`git rm --cached data/clicker.log`：只从索引移除，本地文件保留，忽略规则随即生效。

注意这对其他克隆的表现：拉取后 `data/clicker.log` 会**从工作区被删除**（Git 视之为一次正常的文件删除），程序下次运行会自动重建，不影响使用。
