# 更新日志 — 2026-09-27

记录本次变更，主要内容：新增「窗口区域连点」（`region_click`）动作类型、区域录制器（拖拽圈选 + 窗口拾取）、GUI 第四栏面板、`record_region` 热键（默认 F6）；顺带修复 `save_script` 丢失 `type` 字段与 `list_configs()` 把内置配置文件当成用户配置的问题。

## 主要变更

### 1. 新动作类型 `region_click`（窗口区域连点）

给定一个屏幕矩形区域，鼠标在区域内随机取点 → 在该点连点 N 次（带完整抖动）→ 用 `PathPlanner` 生成拟人相对轨迹移动到下一个随机点 → 循环。

- **纯相对位移注入**：全程只发相对 `move` stroke（`state=0, flags=0`），不使用绝对坐标。因此天然支持多显示器（含负坐标）与光标被游戏锁定的场景，符合项目「锚点零偏差」的设计哲学。
- **首点进入不瞬移**：启动时先 `GetCursorPos` 读当前光标位置，用与后续换点完全相同的相对轨迹移动到区域内第一个随机点。
- **落点抖动不游走**：单次点击的 `x_jitter_px`/`y_jitter_px` 通过「微移 → 按下 → 抬起 → 反向补偿」实现，多次点击的落点彼此独立随机，但 spot 基准点不会随机漂移。
- **可中断**：换点、点击间隔、按住时长、移动过程全部走 `_wait_until_ready` / `_sleep_with_controls`，`F2` 暂停/继续与停止按钮全程生效。
- **不受 `move_mouse` 开关影响**：区域连点以移动为核心，全局「启动时移动鼠标」开关关闭时功能照常工作；启动会额外 toast 说明，避免用户误判。
- **漂移校正**：`correct_drift_px > 0` 时每次换点后比对实际光标位置，误差超阈值就补发一个相对 `move`；设 `0` 关闭。
- **随机取点**：`_pick_spot()` 拒绝采样最多 12 次，要求与上一个点的距离 ≥ `min_spot_distance_px`；全部失败则退回最后一次采样结果，保证不会卡死。
- **扰动能力对齐 `click.json`**：`x_jitter_px` / `y_jitter_px` / `hold_ms`(+jitter) / `interval_ms`(+jitter) / `clicks_per_spot`(+jitter) / `move_duration_ms`(+jitter) / `spot_pause_ms`(+jitter) 全部可配。

### 2. 区域录制器 `RegionSelector.py`（新模块）

只录矩形，不录任何鼠标/键盘事件，因此不与既有 `InputRecorder` 链路混淆。

- **拖拽圈选**：`Toplevel` + `overrideredirect` + `-topmost` + `-alpha 0.3` 铺满整个**虚拟屏**（`SM_X/YVIRTUALSCREEN` + `SM_CX/CYVIRTUALSCREEN`，支持多显示器负偏移），Canvas 画虚线选框，另有独立**不透明**信息浮窗跟随光标显示 `800x600 @ (100,200)`。坐标一律取 `winfo_pointerxy()`，避免 `event.x_root` 在 overrideredirect 多屏下的偏差。`Esc` / 右键取消，宽高 < 4px 视为误操作。
- **窗口拾取**：置顶小窗 3 秒倒计时（`root.after` 驱动，`Esc` 取消）→ `GetCursorPos` → `WindowFromPoint` → `GetAncestor(GA_ROOT)` → 优先 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`（去掉阴影与不可见边框），失败回退 `GetWindowRect`。返回值带 `source="window"` 与窗口标题。
- **主线程约束**：Tk 窗口只能在主线程创建（`DebugOverlay` 的既有结论）。后台热键线程只把请求投递到 `ClickerManager._region_request_queue`，由 GUI 的 `_refresh_loop`（500ms）排空后创建。
- 工具函数 `format_region()` / `get_cursor_pos()` / `normalize_region()` / `capture_window_under_cursor()` 均可独立复用。

### 3. 区域预设持久化

`data/clicker_configs/region_presets.json`，格式 `{"presets": {"名字": {"x":..,"y":..,"width":..,"height":..,"note":""}}}`。GUI 第四栏可存/删/选，手写脚本可用 `"region_preset": "预设名"` 引用。

### 4. GUI 第四栏

主窗口由三栏改为四栏（`minsize` 1720 → 2260，启动宽度 1800 → 2340），四组面板：**目标区域**（预设下拉 + 存/删 + X/Y/宽/高 + 圈选/拾取/录制按钮 + 状态标签）、**点击参数**、**移动参数**、**运行控制**（开始/暂停/继续/停止/保存参数/存为脚本 + 实时统计）。第四栏整体放在可滚动的 Canvas 容器里，小屏也不会遮挡。

### 5. 新热键 `record_region`（默认 F6）

`DEFAULT_HOTKEYS` / `HOTKEY_LABELS` 各加一项。`load_hotkeys()` / `save_hotkeys()` 遍历默认键，`Clicker._hotkey_vk` 用字典推导，`GlobalHotkeyListener` 把所有按键入队由 `_dispatch_hotkey` 过滤 —— 因此监听器无需改动，第四栏的下拉框、彩色徽章、按钮 label 也全部由既有循环自动覆盖。录制中 / 脚本运行中 / 回放中按 F6 会被拒绝并 toast 提示。

## 顺带修复

- **`save_script()` 丢失 `type`**：旧实现写 `[asdict(a) for a in actions]`，产物没有 `type` 字段，`_parse_action()` 回读时全部落到「未知动作类型」分支。改为 `_action_to_dict()`，按 `_ACTION_TYPE_MAP` 补 `type`，并对 `loop` / `timed` 的嵌套 `actions` 递归处理。第四栏的「💾 存为脚本」依赖此修复。
- **`list_configs()` 污染**：旧实现 `CONFIG_DIR.glob("*.json")` 会把 `hotkeys.json` / `path_planner.json`（以及本次新增的 `region_click.json` / `region_presets.json`）当成用户配置列进 CLI 配置管理菜单。新增 `NON_CONFIG_FILES` 排除集一并修好。

## 调试与注意事项

- **`PathPlanner._norm_times()` 在时间跨度 ≤ 0 时返回 `None`，扰动静默失效**：`_build_base_moves()` 合成的基准路径时间戳必须严格递增且 > 0（`t = 总秒数 * (i+1)/steps`），否则 `fitts` / `neuromotor` 会退化成直线且没有任何报错。
- **`dist < 5px` 时 `PathPlanner` 直接返回原路径**，这是预期行为，不需要特判。
- **移动全程忽略 `config.move_mouse`**：该开关语义是「点击前是否把鼠标移到目标坐标」，若受其控制区域连点会完全失效。
- **`path_strategy="global"` 读取 `path_planner.json`**：若第三栏当前保存的是 `straight`，看到的就仍是直线，需要先在第三栏改成 `fitts` / `neuromotor`。
- **Windows「增强指针精度」必须关闭**，否则相对增量会被系统非线性加速，落点与漂移校正都会失准（与既有锚点系统同一个前置要求）。
- **`region_click.json` / `region_presets.json` 是运行期产物**，已加入 `.gitignore`，不要提交用户自己的区域数据。
- 区域录制期间 `F6` 的按键事件仍会被低级钩子看到；若此时恰好在录制输入，该按键可能进入事件流。`_dispatch_hotkey` 已在录制中拒绝弹出圈选窗口，属可接受的边缘情况。

# 更新日志 — 2026-09-27（启动提权与驱动一键安装）

同日第二批变更，主要内容：**用 PyInstaller `--uac-admin` 替掉 `run_clicker.vbs` 做提权**（Windows 11 25H2 起 VBScript 默认被禁用），并**新增驱动一键安装能力**（`DriverInstaller.py` + `install_driver.bat`），让不会敲命令的用户也能装好 Interception 驱动。

## 背景

1. **`.vbs` 不能再用了**。微软已将 VBScript 列为弃用功能，在 Windows 11 24H2/25H2 上它变成了「按需功能」（Feature on Demand）并逐步默认关闭，双击 `.vbs` 可能直接没反应。而 `run_clicker.vbs` 存在的**唯一理由**就是用 `Shell.Application.ShellExecute ... "runas"` 弹 UAC。
2. **驱动安装门槛太高**。原流程要求用户「以管理员身份打开终端 → cd 到 driver_installer → 敲 `install-interception.exe /install` → 重启」，弹窗文案里也只能把这段命令贴给用户看，大量用户卡在这一步。

## 主要变更

### 1. 提权方式：`.vbs` → exe 内嵌清单

`build_release.bat` 的 PyInstaller 命令加上 `--uac-admin`，把 `requireAdministrator` 直接写进 `RocoKingdom_Clicker.exe` 的应用程序清单。用户**双击 exe 就会弹 UAC**，不再需要任何启动脚本，`run_clicker.vbs` 整个删除。

为何选它而不是「再写一个小启动器 exe」：
- 零额外产物、零额外体积，也不存在「启动器与主程序版本不一致」的新失败面
- 提权由系统 loader 在进程创建前完成，比 `ShellExecute("runas")` 更硬：用户无法绕过，也不会出现「启动了但没权限」的半死状态
- `run_clicker.bat` 保留作为源码开发环境的提权入口（`.bat` / cmd 在 25H2 上并未弃用），内部仍用 `Start-Process -Verb RunAs`

### 2. 新模块 `DriverInstaller.py`

把「检测 → 询问 → 安装 → 重启」全部收进程序内部，只用标准库（`ctypes` / `winreg` / `subprocess`），不引入任何新依赖，也不依赖 tkinter（弹框走 `MessageBoxW`，静默启动模式下也可见）。

- **可靠的安装痕迹检测**。Interception 以键盘/鼠标**类过滤驱动**形式安装，服务名就叫 `keyboard` / `mouse`，并没有名为 `interception` 的服务，所以 `sc query interception` 永远返回 1060（这也是旧 `.vbs` / `.bat` 里那段注释记录的假阴性陷阱）。`driver_registry_state()` 改查三个信号（读 HKLM 不需管理员）：类键 `UpperFilters` 是否含 `mouse`/`keyboard`、`Services\mouse` 与 `Services\keyboard` 键是否存在、`%SystemRoot%\System32\drivers\mouse.sys` 是否落地。本机实测：`UpperFilters = mouse\0mouclass` / `keyboard\0kbdclass`。
- **两条提权路径**。`run_installer()` 先看 `IsUserAnAdmin()`：已提权（发布包 exe）→ 直接 `subprocess.run(capture_output=True, CREATE_NO_WINDOW)` 拿完整输出；未提权（源码 `python Clicker.py`）→ 用 `ShellExecuteExW` + `runas` + `SEE_MASK_NOCLOSEPROCESS` 启一个 `cmd /c ""安装器" /install > "日志" 2>&1"`，`WaitForSingleObject` + `GetExitCodeProcess` 取退出码，再回读日志。
  - 日志用**绝对路径**（`%TEMP%\roco_interception_driver.log`）：即使 UAC 里换了一个管理员账号做「过肩提权」，安装器也仍会把输出写回当前用户读得到的位置。
  - `GetLastError() == 1223 (ERROR_CANCELLED)` 单独归为 `cancelled`，与「安装失败」区分开，否则用户点了「否」会看到一堆莫名其妙的错误文本。
- **成功判定不只看退出码**。`_install_succeeded()` 在 `exit_code == 0` 之外额外用官方文案 `successfully installed` 兜底，避开安装器返回码不规范的风险。
- **区分「未安装」与「装了没重启」**。`offer_one_click_install()` 先读注册表：未安装 → 默认焦点在「是」的询问框；已安装但仍不可用 → 先说「最常见原因是还没重启」，默认焦点改到「否」，避免无意义的重装。
- **重启对话框默认选「否」**（`MB_DEFBUTTON2`）。误触回车就会重启电脑，这个默认值必须保守；选「是」走 `shutdown /r /t 15`，文案里直接告知可用 `shutdown /a` 取消。
- **CLI 入口**：`python DriverInstaller.py --status|--install|--uninstall`，`--status` 只读不改系统，方便用户截图反馈。

### 3. 失败原因分类：`InterceptionCore` 新增两个标志

旧版无论什么原因失败，弹窗都叫用户去跑 `install-interception.exe /install`，包括「DLL 根本不存在」和「找不到鼠标设备」这两种重装驱动完全没用的情况。现在：

- `dll_missing`：`ctypes.CDLL` 全部候选路径都失败 → 属打包/解压不完整，**不引导装驱动**，直接叫用户重新下载完整解压
- `driver_install_hint`：`interception_create_context` 抛异常或返回 NULL → 才是「驱动未装/未重启」，可以走一键安装
- 两者都为 `False`（如「没有发现任何鼠标设备」）→ 只给具体原因，不推安装也不推重启

`Clicker._report_driver_not_ready(core, interactive=...)` 是这三路的统一分发器，`main()` / `ClickerManager._show_driver_warning()` / `gui.start_gui()` 全部改成调它，不再各自拼一份提示文案。

### 4. 新脚本 `install_driver.bat`

给「不想先开主程序」的用户一个双击入口，也是程序内弹框被意外关掉后的退路：

- **自提权不用 `.vbs`**：`net session` 判管理员 → 不是则 `powershell Start-Process -FilePath '%~f0' -ArgumentList '%ACTION%','elevated' -Verb RunAs` 把自己重拉一次；`elevated` 标记防止无限自我提权，UAC 被取消时 `catch { exit 1 }` 回传 errorlevel 并给出「已取消」提示而不是闪退。
- 安装器三级回退查找（`driver_installer\` → `third\Interception\command line installer\` → 同级目录）。
- 安装前先用 `reg query ... | find "mouse\0"` 报一下当前状态，帮用户区分「没装」和「装了没重启」。
- 安装器输出重定向到 `%TEMP%\roco_driver_install.log` 再 `type` 出来（它是 CONSOLE 子系统程序，已核实，重定向能拿到文本），失败时既看得到原文也留得到现场。
- 成功后 `choice /c YN` 问是否立即重启，选是则 `shutdown /r /t 15`。
- 全程用 `goto` 标签而不是 `if (...)` 块：`chcp 65001` 下括号块里放中文 `echo` 容易踩到 cmd 的解析坑。
- 支持 `install_driver.bat /uninstall` 卸载。

### 5. 顺手修的编码问题

`run_clicker.bat` 一直是 UTF-8 无 BOM 却没有 `chcp 65001`，里面的【错误】【警告】在默认 GBK 控制台下全是乱码。已补上 `chcp 65001 >nul`（`build_release.bat` 本来就有）。

## 快速验证步骤

1. `python DriverInstaller.py --status` → 已装驱动的机器上五项均为 `True`，并能找到安装器路径。
2. `python -c "from InterceptionCore import InterceptionCore as C; c=C(); print(c.is_ready(), c.dll_missing, c.driver_install_hint)"` → `True False False`。
3. 造一个未就绪场景（把 `interception.dll` 临时改名）跑 `python Clicker.py --gui` → 应弹「文件缺失」而**不是**引导装驱动。
4. 在一台没装驱动的机器（或虚拟机）上双击发布包 exe → UAC → 「是否现在自动安装」→ 是 → 装完问重启 → 选否 → 提示手动重启；重启后直接可用。
5. 同一台机器上再跑一次（已装未重启）→ 应弹「已经安装，最常见原因是还没重启」且默认焦点在「否」。
6. UAC 弹框里点「否」→ 应得到「已取消提权，驱动没有安装」而不是报错。
7. 双击 `install_driver.bat` → 自动提权 → 打印当前状态与安装器输出 → `choice` 问重启；选 N 应停在 `pause`。
8. `install_driver.bat /uninstall` → 卸载后 `--status` 应变为 `False`（记得装回去）。
9. 源码模式下跑 `python Clicker.py --gui`（非管理员）并造一个未就绪场景 → 确认走的是 `ShellExecuteExW + runas` 分支，且能回读到 `%TEMP%\roco_interception_driver.log` 里的安装器输出。
10. `build_release.bat` 重新打包 → 对 `dist\RocoKingdom_Clicker\RocoKingdom_Clicker.exe` 右键属性，或直接用 `mt.exe -inputresource:...exe -out:manifest.xml` 看清单，确认 `requestedExecutionLevel level="requireAdministrator"`；双击 exe 应直接弹 UAC。
11. 确认发布包根目录**没有** `run_clicker.vbs`，**有** `install_driver.bat`。

## 调试与注意事项

- **改完必须重新跑 `build_release.bat`**。`--uac-admin` 是打包期参数，现成的 `dist/` 与 `release/` 里的旧 exe **没有**提权清单，双击不会弹 UAC。本次已顺手删掉了两个目录里残留的 `run_clicker.vbs` 并补上了 `install_driver.bat`，但 exe 本体必须重建。
- **`--uac-admin` 意味着进程全程高完整性**。副作用：从资源管理器拖文件到窗口会被 UIPI 拦住（本项目不依赖拖放，无影响）；非提权进程无法向它发消息。
- **不要把驱动检测改回「查服务名」**。`sc query interception` / 按服务名找 `interception` 都会在驱动正常时误判为未安装，这个坑旧注释里已经记过一遍。
- **`is_driver_installed()` 只能说明「装过」，不能说明「已生效」**。真正能不能用仍由 `InterceptionCore.is_ready()`（能否创建上下文 + 找到鼠标设备）说了算；注册表检测只用来选提示文案。
- **`_show_driver_warning()` 的门闩是故意的**。它会被开始点击 / 录制 / 回放 / 跑脚本四条路径反复调用，不加门闩就会在热键线程上反复弹安装向导。
- **安装器的 CWD 必须设为它自己所在目录**（`run_installer` 里的 `workdir`，`.bat` 里的 `cd /d "%~dp0"`）：官方安装器是 32 位 CONSOLE 程序，从其它目录调用时行为未经验证，不要图省事省掉。
- **`choice` 的 errorlevel 是 1=Y、2=N**，判断必须写 `if errorlevel 2`（含义是 >=2）；写成 `if errorlevel 1` 会永远为真。
- **`.bat` 里的中文靠 `chcp 65001` + UTF-8 无 BOM**。cmd 是逐行按当前代码页解码的，所以 `chcp` 必须放在所有中文行之前；文件不要存成带 BOM 的 UTF-8，否则第一行 `@echo off` 会报错。
