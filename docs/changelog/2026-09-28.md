# 更新日志 — 2026-09-28

记录本次变更，主要内容：新增「MIDI 自动演奏」功能（`MidiScore.py` + `MusicPlayer.py` + GUI 第五栏），给定一套「音 → 键盘按键」的绑定即可自动弹奏任意 MIDI 曲谱；演奏前先做音域检查，缺音时精确指出是哪些音没有绑定。MIDI 解析与演奏引擎全部只用标准库，运行期依赖与发布包体积不变。

## 主要变更

### 1. `MidiScore.py`（新模块）：MIDI 解析 + 键位表 + 可演奏性分析

**为什么不用 mido / python-midi**：本项目其余模块（`InterceptionCore` / `ActionScript` / `PathPlanner` / `RegionSelector` / `DriverInstaller`）同样是零第三方依赖，发布包只带 `interception.dll`，开发环境只需要 Python 3.10。为一个格式简单的二进制文件引入第三方库，会让 PyInstaller 打包和用户环境都多一层安装负担。SMF 的解析量大约 200 行，自己写更划算。

- **解析器**：支持 format 0/1/2、变长数值、running status、sysex 跳过、`note on(velocity=0)` 当 note off、`All Notes Off` / `All Sound Off`（CC 120/123-127）、同音高叠置的 FIFO 配对、缺少 note off 的悬挂音符补到轨道末尾（记 warning，不静默丢音）。
- **速度表**：收集所有轨道的 `Set Tempo`（format 1 里速度常单独放第 0 轨），构造 tick → 秒 的分段线性换算，因此变速曲谱的时间轴是准确的。BPM 字段只取第一个速度用于展示。
- **SMPTE 时基**：`division` 高位置 1 时按「帧率 × 每帧 tick 数」换算，不再当成 PPQ 误读。
- **中文轨道名**：按 UTF-8 → GBK → Big5 依次尝试，且要求结果 `isprintable()`。**故意不做 latin-1 兜底**——部分导出器写进来的轨道名其实是二进制垃圾（示例曲谱 `callofslience.mid` 的三条轨道名就是），latin-1 永远「解码成功」，只会把垃圾变成一串看着像西欧文字的乱码显示给用户；解不出可读文本时退回「轨道 N」。
- **`KeyLayout`**：出厂键位为《洛克王国：世界》手碟九键（与 RocoMusic 练习页一致，中央 C = 60 = C4）：

  | 音 | A2 | E3 | F3 | G3 | A3 | B3 | C4 | D4 | E4 |
  |----|----|----|----|----|----|----|----|----|----|
  | 按键 | B | F | G | H | J | K | T | Y | U |
  | 数字谱 | 低音 6 | 3 | 4 | 5 | 6 | 7 | 高音 1 | 高音 2 | 高音 3 |

  支持增删改、`from_list` 容错重建（单条非法只丢那一条，不会因为一行写坏就把九键全冲掉）、一键多音冲突检测（`conflicts()`）、最近已绑定音查询（`nearest_pitch()`，用于告诉用户「差几个半音」）。
- **`check_score()`**：判定标准很直接——曲谱里出现的**每个**音高，移调后都必须能在键位表里找到按键。只要有一个找不到就 `ok=False`，并给出逐音明细（音名、MIDI 号、出现次数、首次出现秒数、最近的已绑定音、相差半音数），外加两个诊断量：1 秒内的最大音符数（密度过高游戏里来不及抬手）、同键时值重叠数。
- **`find_shifts()` / `best_shift()`**：在 ±24 半音内穷举，按「可演奏音符数降序 → |移调量| 升序」排序，所以第一项就是「能完整演奏且改动最小」的方案；半音阶这类谱子返回 `None`，表示没有任何移调量能救。
- **`build_performance()`**：把曲谱编译成按下/抬起事件序列。核心难点是**同一个键上的音符重叠**——物理键盘和游戏在一个键被按住期间再按一次不会产生第二个音，所以按按键分组后，若下一个同键音符在本次抬起之前就要按下，就提前 `retrigger_gap_ms`（默认 12ms）抬手重触发，保证每个音符都对应一次真实的按下动作。短到做不到时记 `conflicts` 并写 warning。另有 `hold_ratio`（默认 0.9，留出抬手时间）、`min_hold_ms`（默认 45ms，太短游戏识别不到）、`max_polyphony`（0 = 不限；超出时挤掉音高最低的声部，保住旋律）。
- **`MusicLibrary`**：管理 `data/music/`，列表 / 解析名 / 导入（复制进来，重名自动加序号）/ 删除。只认 `.mid` / `.midi`，不扫子目录。

### 2. `MusicPlayer.py`（新模块）：演奏引擎

对外接口与 `PlaybackEngine` 对齐（`start` / `pause` / `resume` / `stop` / `is_playing` / `is_paused` / `toggle_pause` / `get_progress` / `get_loop_progress` / `on_complete(success, stopped)`），因此 `ClickerManager` 和 GUI 可以用同一套状态机管理「回放」「脚本」「演奏」三种会话。

三个实现要点：

- **绝对时间调度**。每个事件的目标时刻 = `起始 perf_counter + 事件时间 / 速度 + 暂停偏移`，不用「sleep(间隔) 累加」的写法，否则误差会随音符数一路累积，一首两分钟的曲子播到后面就明显跟不上拍子。
- **定时器精度**。Windows 默认时钟中断 15.6ms，`time.sleep(0.005)` 实际会睡到 15ms 以上。演奏前 `winmm.timeBeginPeriod(1)` 提到 1ms，`finally` 里 `timeEndPeriod(1)` 还原（不还原会一直拖累整机功耗）。
- **绝不留卡键**。暂停、停止、异常、播完，任何退出路径都走 `_release_all()`；`_held_vks` 集合跟踪当前按住的键。暂停时也会立刻抬手，否则暂停期间某个音会一直响。

暂停的时间轴处理值得单独记一笔：目标时刻**必须在等待循环里每次重算**。最初的写法是在事件循环里算好 `target` 再传给 `_wait_until(target)`，结果暂停期间流逝的时间没有被补进当前正在等待的那个音符——继续之后它按原墙钟时刻触发，等于把音符间隔吃掉了一截，曲子凭空变快。改成 `_wait_until(event_time, speed)` 在循环内重算后才正确，`test_pause_releases_keys_and_shifts_timeline` 专门盯这个回归。

### 3. `ActionScript.py`：新增按键注入原语

- `ActionExecutor.key_down(vk)` / `key_up(vk)`：把按下和抬起拆成两次调用。既有的 `_execute_key()` 是「按下 → sleep(hold) → 抬起」一次完成，无法满足「按住多久由谱子决定」的需求。**未改动 `_execute_key()`**，避免影响既有脚本行为。
- `ActionExecutor.is_keyboard_ready()`：能否找到真正挂了硬件的键盘设备。
- `VK_TO_SCANCODE` 补齐主键盘区标点（`; = , - . / \` [ \ ] '`）与小键盘运算符（`* + - .`）。表里没有的键只能退回 `keybd_event`，游戏里更容易丢键；用户既然可以把音符绑到任意键，就得让这些键真的能走内核注入。

### 4. `ConfigManager.py`：演奏参数持久化

- 新增 `DEFAULT_MUSIC_PLAYER`（键位绑定 + 移调 + 速度 + 保持比例 + 时序参数 + 循环 + 倒计时）、`MUSIC_PLAYER_FILE`（`data/clicker_configs/music_player.json`）、`load_music_player()` / `save_music_player()`。
- 整数字段各带合法区间（`_MUSIC_INT_RANGES`），脏数据**夹回边界**而不是让整个配置回退默认值；`bindings` 单独走 `KeyLayout.from_list` 校验。
- `NON_CONFIG_FILES` 加 `music_player`，避免它被当成用户配置列进 CLI 配置管理菜单（与上次 `region_click` 同一个坑）。

### 5. `Clicker.py`：`ClickerManager` 演奏 API

- 曲谱库在 `__init__` 里 `ensure_dir()`，用户可以直接往 `data/music/` 丢文件。
- 解析结果按 `(路径, mtime)` 缓存，面板反复检查同一首曲子不会重复解析。
- `analyze_music_score(name, shift)` 返回给 GUI 的纯字典结论；`auto_shift` 打开且原调演奏不了时，自动换成 `best_shift()` 的方案并标注 `auto_shift_used`。
- `start_music_play()` 是验收标准的落点：**只有检查通过才允许开演**，否则 toast 直接列出缺哪些音（超过 4 个折叠成「等 N 个音」），并在有可行移调时附一句「改成 X 半音即可完整演奏」。倒计时放在后台线程（`_run_music_session`），不阻塞 GUI，且可被停止取消（`_music_cancel`）。
- 会话互斥：演奏与脚本 / 回放 / 录制互斥，四个方向都加了守卫。录制方向选择**停掉演奏**而不是拒绝——注入的按键会被录制器当成用户输入记下来，录出来的脚本是垃圾。
- `_dispatch_hotkey()` 在演奏（含倒计时）期间只认暂停/继续热键。**这不是可有可无的防呆**：注入的按键同样会被低级键盘钩子看到，用户要是把某个音符绑到 F1-F12，演奏到那个音就会顺带触发录制或圈选。
- `shutdown()` 新增第 2 步停演奏，并置 `_music_cancel`；演奏线程的 `finally` 会把按住的键全部抬起，不能跳过。

### 6. GUI 第五栏

主窗口由四栏改为五栏（`minsize` 2260 → 2460，启动宽度 2340 → 2540；2560×1600 屏幕放得下）。第五栏同样放在可滚动 Canvas 容器里，四组面板：**曲谱库**（列表 + 导入/刷新/删除 + 目录路径）、**键位绑定**（九键徽章 + 音域 + 冲突提示 + 编辑/恢复默认）、**曲谱检查**（移调 + 自动移调 + 结论 + 摘要 + 明细框）、**演奏控制**（6 个参数 + 开始/暂停/继续/停止 + 保存参数 + 进度条 + 状态行）。

- **启动即自动读取曲谱列表**并选中第一首、立刻出检查结论。
- 不能演奏时 `▶ 开始演奏` 变成红色的 `⚠ 无法演奏 · 查看原因`，**按钮保持可点**——点下去弹出完整缺失清单。禁用的按钮点不动，用户就看不到原因了。
- `BindingEditorDialog`：音名（`C4` / `C#4` / `Db4`）或 MIDI 音高数字 + 按键名，逐行改键、删除、新增；保存时校验按键合法性、一键多音冲突、空表。对话框只负责编辑校验，落盘通过回调交回主窗口，配色复用主窗口主题常量。
- 中栏的暂停/继续/停止按钮与左栏状态行都接入了演奏状态；`pause_current` / `resume_current` / `stop_current` 三个 API 现在同时覆盖脚本、回放、演奏。

### 7. 测试（`tests/`，新目录）

`python -m unittest discover -s tests`，106 个用例，纯标准库、不依赖驱动、不需要管理员权限：

- `test_midi_score.py`：用 `_track_from_notes()` 现场合成 SMF 字节流（按秒描述音符 → 绝对 tick → 排序 → delta 编码），因此能精确构造重叠音符、变速、running status、悬挂音符、sysex、GBK 轨道名、二进制垃圾轨道名等边界；另有一条用例拿仓库示例曲谱做端到端校验（276 音符 / 1:51 / 120 BPM，与 RocoMusic 曲谱页标注一致）。演奏序列的不变量用「每个键严格 down/up 交替、结束时全部抬手、按下次数等于音符数」来断言。

## 曲谱为什么不入库

`data/music/*.mid` / `*.midi` 已加入 `.gitignore`，目录本身由 `data/music/README.md` 保留。网上的 MIDI 谱大多是第三方曲目的转录，随仓库和发布包一起分发会有版权问题。功能不受影响：用户把文件丢进目录或用面板导入即可，`_release_copy.ps1` 拷 `data/` 时会自动带上这个目录（只排除 `clicker.log` 与 `clicker_configs`）。

## 快速验证步骤

1. `python -m unittest discover -s tests` → 106 个用例全绿（不需要驱动，也不需要管理员权限）。
2. `python Clicker.py --gui` 启动 → 五栏布局在 2560×1600 上无遮挡，原有四栏功能未回归。
3. 把自己的 `.mid` 丢进 `data/music/` → 点「↻ 刷新」→ 列表出现；或点「📂 导入 MIDI」选一个文件 → 自动复制进来并选中。
4. 选中一首音域在 A2~E4 内的谱子 → 检查区显示 `✅ 可以演奏` + 「N 个音符 · 音域 · 时长 · BPM」，`▶ 开始演奏` 可点。
5. 选中一首超出音域的谱子 → 显示 `❌ 无法演奏：N 个音没有绑定按键`，明细框逐条列出音名/次数/首次时间/最近已绑定音；点红色按钮弹出完整清单。
6. 勾上「自动移调」→ 若存在可行移调，结论自动变绿并标注「已自动移调 ±N」；半音阶谱子仍为红，并提示没有任何移调量能救。
7. 点「✏ 编辑键位」→ 给缺的音补上按键 → 保存 → 徽章与音域刷新 → 重新检查变绿。
8. 倒计时 3 秒内切到游戏窗口 → 演奏开始，进度条与「Ns / Ms · 第 x 轮 / y · 按键 i/j」实时更新。
9. 演奏中按 `F2` → 暂停（按键立刻抬起，不会有音一直响）；再按 `F2` → 继续，节奏与暂停前一致，不会变快。
10. 演奏中点「⏹ 停止」或按停止热键 → 立即停止且无卡键；倒计时阶段停止 → toast「已取消演奏」。
11. 演奏中按 `F6` / `F7` → 被忽略（不会弹出圈选或开始录制）。
12. 速度改 50% / 200% 各跑一次 → 时长相应变化；循环次数改 2、间隔 2000ms → 播两轮且轮间有停顿。
13. 「💾 保存演奏参数」→ 重启程序 → 参数与键位绑定都还在（`data/clicker_configs/music_player.json`）。
14. 「↺ 恢复默认」→ 键位回到手碟九键。
15. 把 `min_hold_ms` 手改大（如 80）→ 重启 → 短音在游戏里不再丢。
16. `build_release.bat` 打包 → 确认 `dist\RocoKingdom_Clicker\data\music\README.md` 存在，且发布包里**没有**任何 `.mid`。

## 调试与注意事项

- **不要拿 `start_music_play()` 写自动化脚本或测试**：它检查通过后会往**当前焦点窗口**注入真实按键。验证只读链路请用 `analyze_music_score()`；`tests/` 里一律用 `FakeExecutor`。
- **`_show_driver_warning()` 会弹模态框，甚至提议重启电脑**。在脚本里验证 `start_music_play()` 的拒绝路径时，驱动未就绪会先撞上它而挂住，要验提示文案请直接调 `_missing_toast_text(analysis)`。
- **面板上的 `hold_percent` 与配置里的 `min_hold_ms` / `retrigger_gap_ms` 是两套东西**：前者是「按住占音符时值的比例」，后两者是绝对下限。游戏识别不到短音时调 `min_hold_ms`；同键快速重复音丢音时调小 `retrigger_gap_ms`（但太小可能被游戏当成一次按下）。
- **音高编号约定是中央 C = 60 = C4**。有些制谱软件用 C3 = 60 的约定，那种谱子会整体差一个八度，用「移调 ±12」修正即可。
- **`max_polyphony` 挤掉的是音高最低的声部**（旋律通常在高声部）。多轨编曲的谱子直接演奏会同时按下很多键，游戏里未必都能发声，必要时限制到 3~4。
- **演奏期间 `F2` 之外的热键被刻意忽略**。如果以后要加「演奏中停止」的独立热键，必须在 `_dispatch_hotkey()` 的演奏守卫里放行，否则按了没反应。
- **`music_player.json` 是运行期产物**，已加入 `.gitignore`，不要提交用户自己的键位与参数。
- **`_release_copy.ps1` 无需修改**：它整目录拷 `data/`（只排除 `clicker.log` 与 `clicker_configs`），`data/music/` 自动进包。`MidiScore` / `MusicPlayer` 被 `Clicker.py` 静态导入，PyInstaller 的导入图能自动发现，不需要加 `--hidden-import`。
