## 3. 订正：曲谱**确实**会随发布包分发

写署名时发现 `data/music/README.md` 与 `docs/changelog/2026-09-28.md` 的说法与事实相反。

**事实**：`dist\RocoKingdom_Clicker\data\music\` 里有全部 6 个 `.mid`，`release\RocoKingdom_Clicker.zip` 里也有。

**根因**：`.gitignore` 只约束版本库，约束不了 `_release_copy.ps1`。后者按顶层条目枚举 `data/`，只排除 `clicker.log` 与 `clicker_configs`，其余整目录递归复制 —— `data/music/` 下的 `.mid` 自然一并进包。09-28 的「快速验证步骤 16」断言"发布包里没有任何 `.mid`"，那条是在一台 `data/music/` 为空的机器上跑的，所以当时确实通过了。

**决定**：保留随包分发，改文档并署名（不是改打包脚本排除）。已就地订正：

- `data/music/README.md`：原「随仓库和发布包一起分发会有版权问题 / 这个 README 只是为了让空目录能被保留」改为「不入 Git，但本地打包会把开发机曲谱复制进发布包」。
- `docs/changelog/2026-09-28.md`：「曲谱为什么不入库」一节加 2026-10-03 订正块；步骤 16 那半句用删除线标出作废并说明理由。仓库有就地订正的先例（09-28 自己就订正过 09-27 的步骤 7）。

**一个连带差异必须记下来**：CI 构建的包**不含** `.mid`。GitHub Actions 从干净的仓库检出，曲谱不入 Git 所以根本不在检出内容里，`data/music/` 只有 README。也就是说 GitHub Release 上的 zip 与本机 `build_release.bat` 产出的 zip 内容不一致。这一点已写进 `data/music/README.md`、`docs/releases/v1.7.md` 的 CI 小节与升级注意事项。
