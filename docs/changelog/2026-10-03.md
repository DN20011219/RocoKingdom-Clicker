## 5. 区域连点：运行时常驻边框

第四栏「运行控制」新增 `🔲 运行时显示区域边框` 开关（默认打开）。勾选后连点期间区域四周常驻一圈青色边框，用来确认鼠标确实落在预期范围内 —— 此前区域一旦圈定、遮罩消失，就只剩 X/Y/宽/高 四个数字，运行时完全看不到框在哪。

### 难点不是画框，是穿透

区域连点靠 Interception 注入相对位移，注入的点击会落到**光标下最上层的窗口**。一个普通的 topmost 覆盖层会把区域内的点击全部吃掉，功能直接失效 —— 不是"稍微挡一下"，是完全点不到游戏。所以覆盖层必须点击穿透。三层保障按可靠性递减（完整理由记在 `RegionOutline` 的 docstring 里）：

1. **边框画在区域外侧**。`outline_geometry()` 把窗口做成区域每边外扩 `border + margin` = 4px；Tk 的线宽居中于路径，`_draw()` 把路径取在 `pad - border/2`，于是线带覆盖 `[2,4]` 而区域从 `4` 开始，只相邻不重叠。这一层不依赖任何分层窗口或 Win32 支持，是兜底。
2. **Tk `-transparentcolor`**：颜色键 `#ff00fe` 的像素完全透明且不参与命中测试，窗口内部天然穿透。
3. **`WS_EX_LAYERED | WS_EX_TRANSPARENT`**：让边框线本身也穿透。

**失败安全**：第 2、3 层都拿不到时（窗口会整个吃掉点击），构造函数销毁窗口并抛 `RegionOutlineUnavailable`，`_sync_region_outline()` 据此跳过显示并 toast 一次。宁可什么都不显示，也绝不放一个会吞点击的窗口上去。

### 实现要点

- **`RegionSelector.py`**：新增 `outline_geometry()`（纯计算，可脱离 Tk 单测）、`RegionOutline`、`RegionOutlineUnavailable`、常量 `OUTLINE_BORDER` / `OUTLINE_MARGIN` / `OUTLINE_COLORKEY`。
- **另开 `ctypes.WinDLL("user32")` 实例**设 argtypes：`ctypes.windll.user32` 是进程内共享对象，在它上面改会波及其它模块（`DriverInstaller.py:257` 已有另开实例的先例）。顺带记一笔：`WindowFromPoint` 的 POINT 是**按值传递**，不设 argtypes ctypes 会传错，验证脚本一开始就踩了这个。
- **拿 HWND 三途径依次尝试**：`wm_frame()` → `GetParent(winfo_id())` → `winfo_id()`。overrideredirect 窗口下 `wm_frame()` 普遍认为会返回 `0x0`，本机实测返回正常值（`0x930c20`），但后两条兜底保留 —— 这是三层保障里最不可靠的一层。
- **后端一行未改**。`get_region_status()` 只返回 `active` / `total_clicks` / `spots_visited`，不含区域矩形，但 GUI 自己有 X/Y/宽/高 输入框，`_current_region()` 现成可用。
- **生命周期挂在已有的 500ms 轮询上**：`_update_region_ui()` 每拍调 `_sync_region_outline()`；区域未变时立刻返回，否则每 500ms 建销一次 Toplevel 会肉眼可见地闪。停止 → `region_click_active` 掉下来 → 销毁，异常路径同样覆盖，不留残窗。运行中途改 X/Y/宽/高 会重建。创建失败时也记下区域，避免每拍重试。
- **开关不落盘**。它是纯显示偏好，塞进 `region_click` 配置要跟着动 `RegionClickAction`（25 个字段）、`DEFAULT_REGION_CLICK`、`_parse_region_click` 的未知字段处理，不值得。代价是每次启动回到默认打开。

### 实测（真机，非桩）

单元测试用记录桩替换了 `RegionOutline`（真建 Toplevel 会往屏幕上画东西，穿透路径又依赖真实 HWND，不适合在测试里跑），所以另跑了一次真机验证，判据是 `WindowFromPoint`：

| 检查 | 结果 |
| --- | --- |
| 区域中心命中的 HWND | 覆盖前 `0x50656` → 覆盖后 `0x50656`，**未变** |
| 边框线上命中 | `0x50656`，不是覆盖层 |
| `wm_frame()` | `0x930c20`（非 0） |
| `GWL_EXSTYLE` | `0x800a8`，含 `WS_EX_LAYERED`(0x80000) + `WS_EX_TRANSPARENT`(0x20) |
| `-transparentcolor` / `-topmost` | `#ff00fe` / `1` |
| Canvas 矩形路径 | `[3.0, 3.0, 405.0, 305.0]`（400×300 区域 + 4px 留白） |
| 销毁 | 无残窗 |

`WindowFromPoint` 前后返回同一个 HWND，就是"注入的点击能打到游戏"的等价证明。验证脚本是一次性的，跑完即删。

### 已知限制

独占全屏（exclusive fullscreen）游戏里覆盖层画不出来，这是 Windows 桌面合成的限制，不是实现问题；无边框窗口化正常。画不出来时不影响连点本身。

## 6. 区域连点：平滑度重做（消除"点击后弹回原位"与短程乱跑）

使用反馈原话：「使用平滑度很差，鼠标点击后感觉在随机跑动一样，我希望是通过总相对位移量来控制鼠标在圈选范围内的，而不是点击一次后又归位，然后再选择下一个位置」「默认策略选择更平滑的策略，不要出现鼠标震颤的情况」。

### 三个根因

1. **`_click_at_spot` 的反向补偿**。落点抖动实现为「微移 +jitter → 按下 → 抬起 → 反向补回 −jitter」，目的是让 spot 基准不随点击次数游走。代价是每次点击后鼠标**弹回原位**，`clicks_per_spot=3` 时一个点来回 6 趟 —— 这就是反馈里的"点击一次后又归位"。
2. **`_correct_drift` 单 stroke 瞬移**。偏差超阈值时把 `dx, dy` 一次性甩过去，视觉上就是突然一跳。
3. **默认策略在短程换点上扰动过大**。`path_strategy` 默认 `global` → 跟随第三栏的 `fitts`（2px 高斯微抖 + 30% 概率 4.5~15px 过冲再拉回）。而 `PathPlanner._sine_strategy` 的振幅是 `rng.uniform(amplitude*0.5, amplitude)`，**固定像素、不随距离缩放**，全局默认 10px 叠在 `min_spot_distance_px=40` 的短程移动上，再乘 `randint(freq, freq+2)` = 2~4 个周期，就是 40px 里塞 4 个 ±10px 的波。

根因 1、2 的共同前提是**位置靠理论值推算**：`spot` 是"应该在的地方"，实际光标可能已经偏了，所以需要事后补偿/校正。

### 修复：改为位置读回

核心是一句话 —— **每段移动结束后读回真实光标位置，作为下一段位移的起点**。

- 新增 `_read_cursor_or_none()`：与 `_get_cursor_pos()` 同样读 `GetCursorPos`，但用 `None` 表示失败。原方法拿 `(0,0)` 当失败哨兵，而 `(0,0)` 同时是虚拟屏原点的合法坐标，两者无法区分；区域连点用它算位移，判错一次就会甩出一个从屏幕原点出发的巨大位移量。
- 新增 `_read_cursor(fallback)`：读失败就当作"已到位"（本段不移动），比拿 `(0,0)` 算安全。
- `_execute_region_click`：首点进入与每次换点的 `dx, dy` 都改成 `目标 − 读回位置`；`_pick_spot` 的最小距离参照也从理论 `spot` 换成读回的 `current`。
- `_click_at_spot`：**删掉反向补偿**，抖动只出去不回来。基准会游走几个像素，但下一段从读回位置算，游走不跨段累积 —— 补偿存在的唯一理由消失了。
- `_correct_drift`：默认关闭（`correct_drift_px` 4 → 0）。保留是给"运行中途用户把鼠标拖走"用的，开启后也改为分多步插值（约每 8px 一步、夹在 2~12 步），不再单 stroke 甩。

### 默认策略与参数

`DEFAULT_REGION_CLICK` 与 `RegionClickAction` **两份默认值同步**改为：

| 字段 | 旧 | 新 |
| --- | --- | --- |
| `path_strategy` | `global`（→ fitts） | `sine` |
| `correct_drift_px` | `4` | `0` |
| `path_params` | `{}` | `{"sine_amplitude_px": 3.0, "sine_frequency": 1}` |

两份必须同步：面板走 `DEFAULT_REGION_CLICK`，手写脚本经 `_parse_region_click` 走 `RegionClickAction()`（它取 `defaults = RegionClickAction()`）。只改一份的话，脚本里省略字段就会悄悄退回旧行为 —— 已加 `DefaultsTest.test_dataclass_and_config_defaults_agree` 逐字段锁住。

顺带修 `_parse_region_click` 的 `path_params`：原先 `item.get("path_params") or {}`，省略时得到空 dict，而空 dict 意味着 PathPlanner 用**全局的 10px 振幅**。改为回落到数据类默认。

**没有动 `PathPlanner`**。振幅不随距离缩放是它的固有设计，改它会同时影响第三栏的录制回放（那套参数有 08-01 的研究依据与既有调校），超出本次范围。区域连点通过已有的 `path_params` 覆盖机制单独调温和，是更小的改动面。

### 实测（40px 典型换点，400 次采样取最差值）

| 配置 | 垂直偏移 | 过冲 | 路径/直线 | 变号次数 |
| --- | --- | --- | --- | --- |
| 改动前 `global` → `fitts` | 4.0px | **8.0px** | 1.45 | 0 |
| 改动前若为 `sine` @ 10px | **10.0px** | 0 | **2.88** | 7 |
| **改动后 `sine` @ 3px** | 3.0px | 0 | **1.29** | 3 |
| 参照 `straight`（无扰动） | 0 | 0 | 1.00 | 0 |

`fitts` 的垂直偏移只有 4px，但**沿轨迹方向过冲 8px 再拉回** —— 只量垂直偏移会低估它，第一次测量就漏了这项，补上后才是真实图景。路径长度 2.88 倍意味着鼠标实际走了近三倍的路。

每点连点 3 次的 move stroke 数：**6 → 3**，且净位移从"0（弹回原位）"变成"≤9px 自然游走"。

终点精度未受损：`test_endpoint_is_still_exact` 对 4 组位移断言总位移正好等于目标。

这对所有升级用户同样成立，已写进 `docs/releases/v1.7.md` 的升级注意事项第 10 条：要么在面板把策略改成 `sine` 再「💾 保存参数」，要么删掉该文件让程序按新默认重建（命名预设存在 `region_presets.json`，不受影响）。
